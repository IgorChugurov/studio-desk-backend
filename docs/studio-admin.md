# Вход в админку студии

**Канон:** `studio-desk-docs/01-product/studio-admin/overview.md`, `studio-desk-docs/03-architecture/authentication.md`
**Контракт:** `studio-desk-docs/01-product/studio-admin/api-contract.md`

Семь адресов под `/api/studio/auth`: запросить код, войти, выбрать студию, сменить студию, обменять код входа под студией, обновить вход, выйти. Короткий токен живёт 15 минут и в базе не хранится. Долгий токен лежит в cookie `sd_studio_refresh` (путь `/api/studio/auth`), в базе только его хеш. `GET /me` отдаёт роль, разделы и язык интерфейса. `PATCH /me/language` запоминает язык по почте. Пока строки нет, в ответе `interfaceLanguage` равен `null`, интерфейс на английском. Сервер cookie языка не ставит.

## Таблицы

- `studio_sign_in_code` — один текущий код на адрес, как `sign_in_code` платформы, но отдельная таблица: один e-mail может запросить код в обоих API, и коды не перезаписывают друг друга.
- `studio_session` — один вход одного человека в одну студию: `studio_id`, `email`, хеши refresh-токенов, `impersonated_by` (заполняется обменом кода входа под студией). Студия сессии не меняется.
- `studio_selection_ticket` — билет выбора студии, одноразовый, 300 секунд. В базе хеш. Список студий в билете не хранится: при выборе он считается заново. Новый билет заменяет все прежние билеты этого e-mail (они удаляются), заодно удаляются чужие билеты, протухшие больше часа назад.
- `studio_staff` — сотрудники студии: `studio_id`, `email`, `role` (`administrator` или `accountant`). Вход только читает её; управление сотрудниками приходит в фазе 5. Владелец в этой таблице не хранится, он записан в `studio.owner_email`.
- `currency` — разрешённые валюты: `EUR`, `UAH`, `USD`. Список заполняет миграция. Настройки студии лежат на самой строке `studio`: `language`, `country`, `currency`, `time_zone`. У новой и у уже существующей студии стоят English (`en`), Словакия (`SK`), евро, `Europe/Bratislava`.
- `role_section` — какие разделы открыты роли. Строка значит «да». Миграция заполняет её один раз. У тренера расписание, клиенты и учёт отмечены как открытые; «только свои» решают темы этих разделов.
- `interface_language` — язык интерфейса человека: почта и `en`, `sk` или `uk`. Одна строка на почту, общая для всех его студий. Нет строки — английский.

`studio_api` читает `studio`, читает и меняет `studio_staff` и `interface_language`, читает `role_section` и `currency`, меняет только поля настроек и `updated_at`, читает и пишет сессии, коды и билеты ещё и удаляет, читает код передачи и помечает его использованным. `platform_api` читает сотрудников и может отозвать сессии студии: при выключении студии и при смене владельца. `public_api` к этим таблицам не допускается. Права выданы в миграциях `0004`, `0005` и `0006` и записаны в `src/database/expected-grants.ts`.

## Настройки студии

`GET /settings`, `GET /settings/options`, `PATCH /settings`. Только владелец, в том числе сессия входа под студией: адрес сессии совпадает с `studio.owner_email`. Сотрудник получает `403`. Пустое поле — ошибка, старое значение остаётся. Неприсланное поле не меняется. Язык — `en`, `sk` или `uk`. Страна — назначенный код ISO 3166-1 из двух букв. Часовой пояс — имя из списка поясов IANA среды выполнения. Валюта — код из таблицы `currency`. Регистр не исправляется: `sk` и `eur` не подходят.

## Кому можно войти

Активные студии человека: те, где он владелец (`studio.owner_email`), и те, где он сотрудник (`studio_staff`). Деактивированные студии не считаются. Письмо с кодом уходит, только если такая студия есть, ответ при этом одинаковый. Правильный код для e-mail без активной студии отвечает как неверный и тратит попытку.

После правильного кода: одна студия — сессия сразу; несколько — сессии нет, в ответе билет и список студий по названию.

## Токены

Общая часть с платформой лежит в `src/common/auth/` (`tokens.ts`, `cookies.ts`, `mailer.ts`). Токен студии содержит `sub` (e-mail), `sid`, `api: "studio"` и `studio_id`. Токен платформы в API студии не принимается, и наоборот. Guard студии на каждом запросе проверяет подпись, срок, живую сессию и совпадение `studio_id` сессии с токеном.

## Коды ошибок

`RESEND_TOO_EARLY`, `INVALID_CODE`, `CODE_EXPIRED`, `TOO_MANY_ATTEMPTS`, `SESSION_EXPIRED`, `INVALID_SELECTION_TICKET`, `INVALID_HANDOFF_CODE`. Нет cookie при обновлении входа — `UNAUTHORIZED`. Нет заголовка `X-Requested-With` на обновлении, выходе, смене студии и обмене кода передачи — `FORBIDDEN`. Студия не принадлежит человеку или деактивирована — `NOT_FOUND`.

Выключение студии в API платформы отзывает открытые сессии этой студии, кроме сессий входа под студией. Смена владельца отзывает все сессии прежнего владельца в этой студии, включая вход под студией. Если новый адрес уже есть среди сотрудников этой студии, смена не проходит (`OWNER_IS_STAFF`), владелец остаётся прежним.

## Проверка

Интеграционные тесты: `test/studio-auth.e2e-spec.ts`. Ручная проверка: `StudioDesk_Studio.postman_collection.json`, локально `http://localhost:3000/api/studio`. Для ручной проверки в базе должны быть студия и, при необходимости, строка в `studio_staff` (сотрудников пока не создаёт ни один адрес API).
